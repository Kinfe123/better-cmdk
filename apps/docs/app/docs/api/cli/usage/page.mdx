# CLI Usage

The repository exposes a command-line entrypoint and runtime flags.
## Command Purpose
The CLI entrypoint is a developer workflow. This page explains what command-line options exist, what configuration they depend on, and how to verify the command did what the repository says it does.
## How to Run It
Run `bun run dev` from the project root after dependencies and required environment values are ready.
Install dependencies first with `bun install`.
## What the Command Depends On
The command reads environment-backed configuration. Set these values before using large runs or automation.
- `npm_lifecycle_event`
- `BETTER_CMDK_TELEMETRY_DISABLED`
- `NEXT_PUBLIC_POSTHOG_KEY`
- `NODE_ENV`
## Flags and Options
Use flags to override defaults for a specific run. Prefer the default script first, then add flags when you need a different scale, concurrency level, target, or debug mode.
- `--cmdk-mobile-sheet-top-inset`
- `--cmdk-input-row-height`
- `--cmdk-mobile-keyboard-inset`
- `--bcmdk-background`
- `--cmdk-item-height`
- `--tw-ring-color`
- `--cmdk-radius`
- `--publish`
## Useful Commands
- `dev` runs `turbo run dev` and starts the local development workflow.
- `dev:web` runs `turbo run dev --filter=@better-cmdk/web` and starts the local development workflow.
- `dev:docs` runs `turbo run dev --filter=@better-cmdk/docs` and starts the local development workflow.
- `build` runs `turbo run build` and creates the production build or compiled package artifacts.
- `typecheck` runs `turbo run typecheck` and supports the project workflow.
- `build:web` runs `turbo run build --filter=@better-cmdk/web` and creates the production build or compiled package artifacts.
## Verification Checklist
- Confirm required environment values are present before running the command.
- Start with the smallest safe command or script before increasing scale.
- Use `--help` when available to confirm the flags supported by the current version.
- Check the command output or downstream service to confirm the expected side effect happened.
